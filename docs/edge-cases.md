# Крайние случаи и параллельность

Что делает система в нестандартных ситуациях. У каждого случая указано, чем
поведение подтверждено: тестом (`tests/…`) или кодом. В конце — известные
ограничения и идеи, как их закрыть.

## Параллельные действия

| Ситуация | Что происходит | Подтверждение |
|---|---|---|
| Два покупателя одновременно берут последние доски | Строки товаров блокируются (`SELECT … FOR UPDATE`) до конца транзакции: второй заказ ждёт и видит уже уменьшенный остаток — продать больше, чем есть, нельзя | `test_order_concurrency.py` |
| Параллельные заказы одних товаров в разном порядке (доска+брус и брус+доска) | Все товары заказа блокируются одним запросом **в порядке id** — одинаковый порядок исключает взаимную блокировку (deadlock), ни один заказ не падает | `test_parallel_orders_with_reversed_items_do_not_deadlock` |
| Покупатель отменяет заказ в тот же момент, когда админ его подтверждает | Обе операции блокируют строку заказа. Вторая видит уже новый статус и получает 400: отмена возможна только из «Нового», а подтверждение — только из «Нового» | `orders.cancel_order`, `ALLOWED_TRANSITIONS` |
| Двойная отмена (двойной клик, повтор запроса) | Повтор получает 400 — заказ уже «Отменён», товар возвращается на склад один раз | `test_customer_cannot_cancel_non_new_order` |
| Два админа жмут разные кнопки статуса в Telegram | Строка заказа блокируется; второй получает «Статус уже изменён — обнови карточку» | `run_telegram_bot.admin_change_status` |

## Склад, штуки и кубы

| Ситуация | Что происходит | Подтверждение |
|---|---|---|
| В кубе 27,33 доски | Продаётся 27 штук в кубе: дробная часть отбрасывается (BR-03) | `test_pieces_in_cubic_meter_rounds_down` |
| Погрешность float: 1 / 0,05 = 19,999… | При округлении добавляется допуск 1e-9 — получается ровно 20, а не 19 | `test_pieces_in_cubic_meter_rounds_down` |
| В корзине и кубы, и штуки одного товара | Списания складываются в базовых единицах и проверяются по общему остатку; на сайте кнопка «+» блокируется по тому же правилу | `test_pieces_and_cubes_share_stock` |
| Заказ на 1,5 куба | 400 — кубы и штуки только целые; крепёж в кг можно дробно | `test_fractional_cubes_are_rejected`, `test_fasteners_allow_fractional_kilograms` |
| Не хватает одной позиции из нескольких | Ничего не списывается: остаток проверяется по всем позициям до списания | `test_order_does_not_partially_change_stock` |
| После заказа поменяли длину доски (сменилось число штук в кубе), затем заказ отменили | На склад возвращается столько штук, сколько было списано: коэффициент сохранён в позиции заказа | `test_cancel_uses_snapshot_after_dimensions_change` |
| Доска больше 1 м³ | Продавать её кубами нельзя — 400 | `variant_service.recalc_cubic_variants` |
| Заданы не все размеры или единица не «шт» | 400 — размеры только целиком и только для штучного товара (BR-04) | `test_partial_dimensions_are_rejected`, `test_dimensions_require_piece_unit` |
| Удаляют вариант, который есть в старых заказах | Вариант скрывается, а не удаляется — история заказов цела | `test_variant_used_in_orders_is_deactivated_not_deleted` |
| Удаляют или скрывают последний вариант | 400 — у товара всегда есть способ продажи | `test_cannot_remove_last_active_variant` |
| Передали вариант другого товара | 404 | `test_variant_of_other_product_is_rejected` |

## Корзина и оформление

| Ситуация | Что происходит | Подтверждение |
|---|---|---|
| Цена изменилась, пока товар лежал в корзине | Сумму пересчитывает сервер по текущим ценам; цены в браузере только предварительные (BR-12) | `orders.create_order` |
| Товар скрыли, пока он в корзине | Заказ получает 404 с номером товара, покупатель видит сообщение об ошибке | `test_customer_cannot_order_inactive_product` |
| Токен входа истёк прямо во время оформления | Сайт сбрасывает сессию и просит войти снова; корзина остаётся | `App.handleCheckout` |
| Самовывоз без адреса | Адрес не нужен, сохраняется «Самовывоз со склада» | `test_pickup_order_without_address` |
| Доставка без адреса | 422 — адрес не короче 5 символов | `test_delivery_requires_address` |

## Telegram и уведомления

| Ситуация | Что происходит | Подтверждение |
|---|---|---|
| Telegram недоступен при запуске бота | Бот не падает: повторяет попытки с паузой 3 → 6 → … → 60 с | `run_telegram_bot.main` |
| Telegram недоступен во время заказа | Заказ сохраняется; уведомления уходят после ответа покупателю, ошибка только в логе (BR-24) | `order_notifications.notify_order_event` |
| Сервер в России не достаёт до `api.telegram.org` | `TELEGRAM_API_URL` — бесплатный посредник на Cloudflare Workers (`deploy/telegram-relay-worker.js`), или `TELEGRAM_PROXY` (socks5/https). Сайт работает напрямую | `test_api_url_can_point_to_relay` |
| Покупатель вышел из бота | Сообщения о заказах больше не приходят (BR-23) | `test_logged_out_customer_gets_nothing` |
| Админ сам сменил статус | Остальным админам — уведомление, ему — нет | `test_admin_who_changed_status_is_not_notified` |
| Тесты запускаются на машине с настоящим токеном | `conftest.py` обнуляет токен: тесты никогда не пишут в настоящий Telegram | `tests/conftest.py`, `test_telegram.py` |

## Аккаунты и роли

| Ситуация | Что происходит | Подтверждение |
|---|---|---|
| Зарегистрирован «+7 999…», входит как «8 999…» | Это один номер — вход проходит; второй аккаунт на него не создать (BR-26) | `test_auth_lookup.py` |
| Telegram на телефоне сделал первую букву email заглавной | Email сравнивается без учёта регистра | `test_admin_email_login_ignores_case` |
| Обычный админ пытается назначить админа | 403 — это может только владелец, в том числе через `PATCH /users/{id}/role` | `test_regular_admin_cannot_promote_via_role_endpoint` |
| Пытаются снять права с владельца | 400 | `test_owner_cannot_be_removed` |
| Назначают админом незарегистрированный номер | 400 с понятным текстом: сначала зарегистрироваться на сайте | `test_add_unknown_user_gives_clear_error` |
| Сервер запущен без `SECRET_KEY` | Backend не стартует (BR-30) | `auth.py` |
| Подбор пароля на сайте | После 10 неудачных попыток за 5 минут — 429 и время ожидания (BR-32) | `test_login_attempts_are_limited` |
| Подбор пароля через бота | После 5 попыток за 10 минут бот просит подождать | `test_telegram_login_is_limited_per_user` |
| Пароль короче 8 символов при регистрации | 422; старые короткие пароли при входе работают (BR-31) | `test_short_password_is_rejected_on_register`, `test_old_short_password_still_logs_in` |
| Ошибка в коде пытается записать остаток −1 или статус «LOST» | База отклоняет запись, транзакция откатывается (BR-33) | `test_database_rejects_negative_stock`, `test_database_rejects_unknown_order_values` |
| 3 кг саморезов по 1,10 ₽ | В float было бы 3,3000000000000003 — деньги хранятся в `NUMERIC(12, 2)`, сумма ровно 3,30 ₽ | `test_money_is_exact_numeric` |
| Покупатель выбрал самовывоз | Этапа «В пути» нет: «Готов к выдаче» → «Выдан»; кнопка «В пути» не показывается, а запрос на неё — 400 (BR-16) | `test_pickup_skips_on_the_way` |
| Время в браузере покупателя | Сервер отдаёт время с пометкой UTC — браузер показывает его по местному времени, без сдвига на 3 часа | `test_times_are_sent_as_utc` |
| Регистрация без галочки согласия | 422 — без согласия с политикой аккаунт не создаётся (BR-34) | `test_register_requires_privacy_consent` |
| Старые заказы прошли этап «Водитель назначен» | Этап убран; в истории старых заказов он остаётся с подписью | миграция `c3d9a1f40b27` |

## Известные ограничения и идеи

| Ограничение | Чем грозит | Идея |
|---|---|---|
| Уведомления отправляются фоновой задачей после ответа | Если процесс упадёт между сохранением заказа и отправкой — сообщение в Telegram потеряется (заказ при этом цел) | **Transactional Outbox**: событие пишется в таблицу в той же транзакции, что и заказ, а бот отправляет и помечает доставленным |
| Счётчики лимитов хранятся в памяти процесса | При перезапуске сбрасываются; при нескольких процессах API лимит считается в каждом отдельно | Redis, если магазин вырастет до нескольких серверов |
| В истории статусов не записано, кто сменил статус | Нельзя восстановить, какой админ отменил заказ | Журнал действий (audit log): кто, что, когда |
